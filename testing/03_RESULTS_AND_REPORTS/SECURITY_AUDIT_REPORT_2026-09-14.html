Executive Summary & Key Strengths Antigravity Security Evaluation
Core Security Architecture is Exceptionally Robust: SDTracker demonstrates strong defensive engineering across core business logic. All database routes (/api/db/*) enforce server-side authentication (requireAuth), reject spoofed client headers, and execute through parameterized Supabase client methods with zero raw SQL string concatenation.
✅ Zero SQL Injection Surface

All database interactions in server/routes/db.ts utilize typed ORM builder methods against an explicit table whitelist (ENTITY_REGISTRY). Raw SQL string concatenation is absent.

✅ Zero Cross-Site Scripting (XSS)

The frontend codebase has 0 occurrences of dangerouslySetInnerHTML and 0 occurrences of eval(). React JSX auto-escapes all user input rendered into the DOM.

✅ Timing-Safe HMAC Token Signer

Administrator session tokens in server/tokenSigner.ts use HMAC-SHA256 with crypto.timingSafeEqual, preventing signature forgery and timing side-channel attacks.

✅ In-Memory Brute Force Throttling

Vulnerability Findings & Detailed Code Analysis Severity-Ranked Defect Catalog
SEC-001: Hardcoded Master Administrator Break-Glass Credentials
HIGH SEVERITY CWE-798
Location: server/routes/auth.ts:L86-87
The authentication router contains a hardcoded fallback account: 
const isMasterAccount = (cleanEmail === 'stackmaster@sdcommercial.co.uk' || cleanEmail === 'stackamster@sdcommercial.co.uk') && password === 'Focusmode123!';
Anyone possessing knowledge of this email and static password can authenticate directly against the Express server and receive a signed 12-hour Super Admin session token, bypassing identity provider controls.
Recommended Remediation: Load the master administrative break-glass password exclusively from an environment variable (MASTER_ADMIN_PASSWORD) in .env. In production environments, if the variable is omitted, the built-in fallback account should be disabled.
SEC-002: Known Prototype Pollution & ReDoS in xlsx Dependency
HIGH SEVERITY CVE-2023-30533 / CWE-1321
Location: package.json:L37 • node_modules/xlsx
The xlsx package (^0.18.5) contains two known vulnerabilities:
  • GHSA-4r6h-8v6p-xvw6 (CVSS 7.8): Prototype Pollution in SheetJS parser via crafted Excel workbook payloads.
  • GHSA-5pgg-2g8v-p4x9 (CVSS 7.5): Regular Expression Denial of Service (ReDoS) during cell address parsing.
Recommended Remediation: For client-side Excel exports, migrate from xlsx to the modern, actively maintained exceljs or xlsx-populate library, or install the official patched build from SheetJS CDN (https://cdn.sheetjs.com/).
SEC-003: Overly Permissive Wildcard CORS Matching on .amplifyapp.com
MEDIUM SEVERITY CWE-942
Location: server/index.ts:L152-175
The CORS origin check uses suffix validation: 
if (cleanOrigin.endsWith('.amplifyapp.com') || cleanOrigin.endsWith('.sdcdms.co.uk')) { isAllowed = true; }
Because AWS Amplify allocates public subdomains to any AWS customer (e.g., https://attacker-app.amplifyapp.com), an external attacker could host a malicious web app on Amplify that satisfies this check and successfully makes credentialed cross-origin requests (Access-Control-Allow-Credentials: true) to users accessing the backend API.
Recommended Remediation: Replace the wildcard suffix check with an explicit whitelist of approved application IDs (e.g. main.d25243nvew1u7s.amplifyapp.com) or restrict to your custom domain (*.sdcdms.co.uk).
SEC-004: TLS Certificate Verification Disabled in Postgres Migration Client
MEDIUM SEVERITY CWE-295
Location: server/migrate.ts:L99
During automated schema migrations, the direct PostgreSQL client establishes TLS connections with certificate verification disabled: 
ssl: { rejectUnauthorized: false }
While commonly used to connect to poolers with self-signed intermediate certificates, disabling validation permits Man-In-The-Middle (MITM) interception if network traffic traverses untrusted segments.
Recommended Remediation: In production environments, download the Supabase root CA certificate and specify ssl: { ca: fs.readFileSync('db/ca.crt'), rejectUnauthorized: true }.
SEC-005: Missing Standard HTTP Security Headers (HSTS, CSP, X-Frame-Options)
LOW SEVERITY CWE-693
Location: server/index.ts
The Express HTTP server does not currently attach defense-in-depth headers such as Content-Security-Policy, X-Content-Type-Options: nosniff, X-Frame-Options: SAMEORIGIN, or Strict-Transport-Security.
Recommended Remediation: Install and mount helmet middleware in server/index.ts (app.use(helmet({ contentSecurityPolicy: false }))) to automatically attach all standard security headers.
SEC-006: Unauthenticated Infrastructure Information Disclosure & Probe Endpoints
LOW SEVERITY CWE-200
Location: server/routes/config.ts:L8-47
The routes /api/config/status, /api/config/test-supabase, and /api/config/test-smtp are mounted without authentication:
  • /api/config/status exposes server internal LAN IP addresses (networkIps) and SMTP configuration details.
  • /api/config/test-smtp can be invoked repeatedly by anonymous callers to trigger outbound SMTP socket connections.
Recommended Remediation: Protect /api/config/* with requireAuth or require Admin privilege, or redact internal network IP arrays in production environments.
